## Проблема

> **Пользователь:** Не выполняется terraform init. Не может найти локальный @plugins/terraform-provider-proxmox_v0.114.0. Что не так в конфигурационных файлах?

`terraform init` не мог найти локальный провайдер `terraform-provider-proxmox_v0.114.0`.

## Исходное состояние

### `.terraformrc` (неправильное)
```hcl
provider_installation {
  dev_overrides {
     "bpg/proxmox" = "./plugins"
  }
  direct {
    exclude = ["registry.terraform.io/*/*"]
  }
}
```

### `versions.tf`
```hcl
terraform {
  required_providers {
    proxmox = {
      source = "bpg/proxmox"
    }
  }
}
```

### `terraform.tfvars`
```hcl
virtual_environment_endpoint      = "https://192.168.122.100:8006/"
virtual_environment_ssh_username  = "root"
virtual_environment_api_token     = "******"
virtual_environment_root_password = "******"
```

## Причины ошибок

> **ИИ:** Проблема в том, что `dev_overrides` в Terraform предназначен для **разработки самого провайдера** (когда у вас есть исходный код на Go и Terraform сам делает `go build`). Для **pre-compiled бинарников** (как ваш) `dev_overrides` не работает корректно — Terraform ищет исходники, а не бинарник.

1. **`dev_overrides`** — предназначен для разработки провайдера из исходников на Go, а не для pre-compiled бинарников
2. **`registry.terraform.io` заблокирован** в РФ — провайдер невозможно скачать из реестра
3. **Бинарник назван с суффиксом версии** — Terraform не может его идентифицировать
4. **Неправильная структура каталогов** — провайдер должен лежать в иерархии, повторяющей реестр

## Решение

> **ИИ:** Используйте кэш плагинов вместо `dev_overrides`.

### 1. `.terraformrc` (исправленное)
```hcl
provider_installation {
  filesystem_mirror {
    path = "/home/kirillkonovalov/.terraform.d/plugins"
  }
}
```

`filesystem_mirror` заставляет Terraform искать провайдеры в локальной структуре, повторяющей реестр, вместо попытки скачать их из сети.

### 2. Структура плагинов
```
~/.terraform.d/plugins/registry.terraform.io/bpg/proxmox/0.114.0/linux_amd64/
  └── terraform-provider-proxmox_v0.114.0
```

### 3. `versions.tf` (с объявлением переменных)
```hcl
terraform {
  required_providers {
    proxmox = {
      source = "bpg/proxmox"
    }
  }
}

variable "virtual_environment_endpoint" {
  description = "Proxmox API endpoint"
  type        = string
}

variable "virtual_environment_ssh_username" {
  description = "SSH username for Proxmox"
  type        = string
}

variable "virtual_environment_api_token" {
  description = "API token for Proxmox authentication"
  type        = string
  sensitive   = true
}

variable "virtual_environment_root_password" {
  description = "Root password for Proxmox"
  type        = string
  sensitive   = true
}
```

### 4. Результат `terraform plan`
```
No changes. Your infrastructure matches the configuration.
```

## Ключевые выводы

| Проблема | Решение |
|----------|---------|
| `dev_overrides` для бинарников | `filesystem_mirror` |
| Блокировка реестра в РФ | Локальный mirror вместо скачивания |
| Бинарник с суффиксом версии | Переименовать в `terraform-provider-proxmox` |
| Неверная структура каталогов | Повторить иерархию `registry.terraform.io/<namespace>/<name>/<version>/<platform>` |
| Переменные в `.tfvars` без `variable` блоков | Добавить объявления переменных |
